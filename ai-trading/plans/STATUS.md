# AI Trading: Status

Main tracker for the family AI trading assistant. Child plans and phase details live in `subplans/`. Scratch files go in `../temp/` (gitignored). The four release-1 upstream apps are pinned in `../packages/` as git submodules; deer-flow and AG-UI stay gitignored references. Release 1 is live; pending changes and rollout gates are recorded below.

> `family-app` is a public GitHub repository. Never commit balances, positions, account numbers, broker credentials, or API keys.

## Goal

A private web app (later iPad and iPhone) for two family users:

- Active trading support: technical-analysis Q&A, news- and earnings-driven tactical ideas, scans of preset stock and futures watchlists, backtesting, and forward-testing on an Interactive Brokers paper account.
- Long-term investing support: growth and reasonable-value sector research, covered-call Q&A, covered-call scanning and alerts for hedging and income.

Releases: release 1 (MVP) is a Trading Hub web app for four unmodified upstream apps: TradingAgents, ai-hedge-fund, Vibe-Trading, and experimental MiroFish. Release 2 adds our own solution, the Family Desk, as the hub's fifth app.

## Constraints

- Self-hosted on a VPS or the home Ubuntu server. Never hosted on GCP; light GCP services are allowed.
- LLMs: Anthropic and OpenAI APIs now. A self-hosted DeepSeek model is a distant later option.
- Broker access: Interactive Brokers paper account only. No access to live portfolios.
- Analysis and alerts only. The app never places orders on a live account.
- Web first; native mobile later.

## Release 1 Build Notes (2026-10-04)

- **Terminal/provider repair (live 2026-10-10):** the captive launcher keeps output after a finished, failed, or cancelled run, offers another analysis on Enter, and never reruns on reconnect; the real tmux lifecycle test passes inside both production terminal containers. Vibe-Trading runs on direct OpenAI `gpt-5.5` (no OpenRouter value anywhere; the settings API and persisted settings agree, the key is never copied), and one real completion succeeded with the sponsored key. MiroFish stayed enabled, expense containers were untouched, and upstream sources remain untouched. Smoke/offline suites passed before release. The owner's standing authorization requires automatic `dev` merge, scoped release, deployment, and live verification after each completed phase.
- **Disk incident (2026-10-10):** the first deploy of that release failed with ENOSPC. Each MiroFish-enabled release is about 17 GB with no shared layers, and old tags were never removed, so the 96 GB VPS disk filled; production stayed healthy on the previous release. Old `ai-trading` tags were removed by hand, and PR #72 (released as #76, live and verified) makes `deploy.sh` prune them itself (keeping the new release and the rollback target) and refuse to start below 30 GiB free: the next deploy pruned `ee15c11` unaided and left 34 GB free.
- **Financial Datasets alternatives:** [subplans/01k-ai-hedge-fund-data-options.md](subplans/01k-ai-hedge-fund-data-options.md), a proposal awaiting the owner's choice. It recommends reusing the Desk's free data layer through the wrapper image, as the Desk plan already intends.
- **Open question (owner, 2026-10-10): why does Vibe-Trading have its own hostname, and should every app be a route on `trading-hub`?** Findings from the pinned upstream source: the SPA calls the API through a hard-coded `BASE = ""`, so every call is root-relative (`/api`, `/auth/sse-ticket`, `/sessions`, `/swarm`, `/settings`, `/options`, ...); its router has no `basename`; `index.html` loads `/favicon.svg`, `/fonts/*`, and `/theme-boot.js` from the root; the backend has no root-path or prefix support; and it sends `X-Frame-Options: DENY` with `frame-ancestors 'none'` (D9), so it cannot be embedded either. Mounting it under `/apps/vibe-trading/` would collide with the hub's and MiroFish's `/api/*`. The terminals are routes because ttyd supports `--base-path`. Options: (1) keep the own hostname and link to it from the hub, as now (recommended: no patches, survives weekly upstream bumps); (2) patch Vibe at image-build time (base path, router basename, auth and asset paths, prefix strip in Caddy), which gives up the unmodified-upstream rule (D9) and needs re-verifying on every bump; (3) a rewriting proxy, which is brittle with the SSE and WebSocket traffic. MiroFish looks different (its client reads a build-time `VITE_API_BASE_URL`; its router has no base), so a route may be feasible there after a spike. Awaiting the owner's decision.
